# useDefer
用于分帧渲染大量元素、缓解首屏白屏的 Hook。

## 基础用法
`useDefer` 返回一个判断函数，传入元素下标，返回该元素当前是否可以渲染。
```tsx
import { useDefer } from 'ono-react-element'

function App() {
  const count = 1000
  const defer = useDefer()

  return (
    <div>
      {new Array(count).fill(null).map(
        (_, i) => defer(i) && <div key={i}>第 {i + 1} 个组件</div>
      )}
    </div>
  )
}

export default App;
```

## API
参数|说明|类型|默认值|是否必填
:- | :- | :- | :- | :-
maxCount|**当前实现下不生效**（内部帧计数不会停在它上面），详见注意事项|<code>number</code>|<code>100</code>|否

## 返回值
参数|说明|类型
:- | :- | :-
defer|判断下标为 <code>n</code> 的元素是否已可渲染|<code>(n: number) => boolean</code>

## 注意事项
- **列表是从前往后逐帧长出来的**：`defer(n)` 在内部帧计数**超过** `n` 之后才为 `true`，所以 `defer(0)` 在首帧也是 `false`，第一个元素同样要等一帧。
- **`maxCount` 目前不生效**，别指望它限制帧数：实测传 `maxCount: 5`，内部帧计数在 1 秒内已经涨到 `37` 并且还在涨。也就是说用默认值渲染 1000 个元素，最终 1000 个都会出现，只是需要约 1000 帧。要控制出现进度请在外层自己兜，例如 `defer(i) && i < limit`。
- **帧的推进速度不是稳定的「每帧一个」**：实现里每次渲染都会额外挂一帧回调（实测稳定挂着 4 条回调，并随渲染次数累积），所以推进速度会随渲染次数变化，不要把它当精确的帧计数器用。
- **组件卸载后仍会继续调度帧**：实测卸载之后 5 帧内又新增了 10 次调度（只有最早的一条回调链被取消）。在频繁挂载 / 卸载的场景里要留意这部分空转。
- 返回的判断函数每次渲染都是新闭包，读取的是当前帧计数，直接在渲染里调用即可，不要缓存它。
- 被推迟渲染的元素不占用 DOM，如果需要保持滚动位置稳定，请自行给出占位高度。
