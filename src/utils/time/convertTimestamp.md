# convertTimestamp

把位数不一的秒级 / 毫秒级时间戳统一归一化成 `Date` 对象。

## 基础用法

```ts
convertTimestamp(1735689600000) // 2025-01-01T00:00:00.000Z（13 位毫秒级）
convertTimestamp(1735689600) // 2025-01-01T00:00:00.000Z（10 位秒级）
convertTimestamp(173568960) // 2025-01-01T00:00:00.000Z（9 位，同样按秒处理）
```

后端给秒级、前端存毫秒级是常态，用它做统一入口：

```ts
import { convertTimestamp } from 'ono-react-element'

const date = convertTimestamp(res.timestamp)
console.log(date.getFullYear(), date.getMonth() + 1)
```

## 归一化规则

理解成一个动作即可：**把数字串「右侧补 0 / 截断」到 13 位**。多数情况下不用关心传的是秒还是毫秒：

| 输入位数 | 处理 | 例 |
| :- | :- | :- |
| 13 | 直接使用 | `1735689600000` → `2025-01-01` |
| 大于 13 | 截取前 13 位（低位被丢弃） | `17356896000000` → `2025-01-01` |
| 11 ~ 12 | 末尾补 `0` 至 13 位 | `17356896000` → `2025-01-01` |
| 10 | 乘以 1000（等价于补 3 个 `0`） | `1735689600` → `2025-01-01` |
| 小于 10 | 末尾补 `0` 至 13 位 | `123456789` → `2009-02-13` |

## 注意事项

- ⚠️ **位数过短（小于 10 位）不是报错，而是「补零到 13 位」**：`convertTimestamp(1)` 得到 `2001-09-09`，`convertTimestamp(123456789)` 得到 `2009-02-13`。所以不要把 `HHmmss`（如 `123456`）、`YYYYMMDD`（如 `20240101`）这类「长得像时间、单位却不是时间戳」的数字直接丢进来 —— 它不会拒绝，只会给一个看似合理的错误日期。
- 超过 13 位时是**截断而非四舍五入**：传微秒级（16 位）时，超出部分会被直接丢掉，精度以这种方式悄悄损失。
- 返回 `Date` 对象而非字符串，时区按运行环境解释；要固定展示请配合 `formatTime` / `localFormat`。
- 非法输入不做拦截：`NaN` 得到 `Invalid Date`，负数的结果也不符合直觉，调用前自行校验。
